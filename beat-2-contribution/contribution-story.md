## Reproduction Process

**Environment Setup**

- OS: Windows 11 Home (10.0.26200), Windows PowerShell
- Node v24.13.0, npm 11.6.2, Jest 30.5.0
- Project: my fork of Bashamega/WebDevTools at commit `3b10434c564f1c450e777535e33f6f52456d402f` ("test: add Jest tests for Image Color Picker (#696)"), which was upstream `main` when I fetched it on 2026-11-09.
- Setup: forked and cloned the repo, then ran `npm install`.

Challenge: the npm test scripts set `NODE_OPTIONS` with Unix shell syntax, so on PowerShell I followed contributing.md: set `$env:NODE_OPTIONS` first, then call Jest directly with `npx jest`. My clone is on my branch `feature/asciidoc-editor-tests`, which already has my new test file, so I told Jest to skip that file. That way the run covers exactly the tests upstream main has.

**Steps to Reproduce**

1. `$env:NODE_OPTIONS = "--experimental-vm-modules"`
2. `npx jest --testPathIgnorePatterns asciiDoc --coverage --collectCoverageFrom "src/app/asciiDoc/**"`
3. Observed: all 11 existing suites (54 tests) pass, and the AsciiDoc editor's files, `src/app/asciiDoc/page.jsx` and `components/Editor.jsx`, are at 0% coverage. No test in `__tests__/` touches them.

**Reproduction Evidence**

- **Commit showing reproduction:** none (the evidence is test output on upstream commit `3b10434`)
- **Screenshots/logs:**

```

Tests:       54 passed, 54 total

File                 | % Stmts | % Branch | % Funcs | % Lines | Uncovered Line #s
 asciiDoc            |       0 |        0 |       0 |       0 |

 asciiDoc/components |       0 |      100 |       0 |       0 |
  Editor.jsx         |       0 |      100 |       0 |       0 | 1-3
```

- **My findings:** The issue is real today: upstream main's `__tests__/` has only `customizer/`, `gh-finder/`, `lib/`, and `test.test.jsx`, and there is no AsciiDoc folder. The 100% branch figure on `Editor.jsx` only appears because the file has no branches; none of its lines run. Gap: I ran this on Windows only, using contributing.md's PowerShell commands rather than `npm test`, and I haven't tried macOS or Linux.

The preferred `control-run` check failed, because I collected coverage only for `src/app/asciiDoc/**` with no tested tool beside it for contrast.
- Difficulties: it pointed out that my posted claim breaks my own new voice rule, which is the exact Wrong example in my guide: it names a first step but not when I'll report back. Since the claim was already posted, the grade couldn't change it. It also said the repro was "ready to post", but the assignment says not to post the repro, so I didn't.
