## Solution Approach

**Analysis**

This issue isn't a crash. Part of the app has no tests at all: the AsciiDoc Editor at `/asciiDoc`. Upstream main (`3b10434`) has no `__tests__/asciiDoc/` folder. With the 11 existing suites, `src/app/asciiDoc/page.jsx` and `src/app/asciiDoc/components/Editor.jsx` are both at 0% coverage. Editor.jsx shows 100% branches only because it has no branches.

What the editor does, traced through the code:

- `src/app/asciiDoc/page.jsx` (`AsciiDocEditor`) keeps three pieces of state: `value` (the source text), `HTML` (the rendered output), and `isDarkMode`. On every edit, `handleChange` stores the text and runs `asciidoctor.convert(val)`. The result goes into the preview `<div>` through `dangerouslySetInnerHTML`. `isDarkMode` picks the page colors (`bg-gray-900 text-gray-400` or `bg-white text-gray-800`) and the editor theme (`vs-dark` or `vs-light`).
- `src/app/asciiDoc/components/Editor.jsx` (`CodeEditor`) passes `value`, `onChange`, and `theme` through to `@monaco-editor/react`'s `Editor`.
- The theme isn't stored in the page. The shared `NavBar` (`src/components/navbar.jsx`) reads `localStorage.theme` when the page first loads and calls `toggleTheme` if it's `true`. If the stored value isn't valid JSON, it logs `Failed to read localstorage`. The toggle button writes `!isDarkMode` back to `localStorage`.

Why the page has no tests yet, as far as I can tell: two of its libraries don't load under jsdom. Monaco needs a real browser. The `asciidoctor` package reads `document.currentScript` and `process.argv` when it loads, and both are missing or wrong under jsdom.

**Proposed Solution**

Add one test file, `__tests__/asciiDoc/page.test.jsx`, following the folder layout in contributing.md and the pattern from the recent test PRs (#696, #697). It covers the three areas the issue lists:

- Rendering: the navbar title and toggle, an empty editor and preview, and light mode by default.
- Interactions: real AsciiDoc typed into the editor shows the expected preview, including headings, a document title, bold and italic, lists, links, listing blocks, clearing the text, HTML typed as text, and whitespace only.
- State: the toggle switches the theme and saves it, a stored dark or light theme is applied on load, and an invalid stored value falls back to light mode.
- Workflow (integration): a full document, editing and then switching theme, and dark mode surviving a reload.

Monaco is mocked as a `<textarea>` that passes the same `value`, `onChange`, and `theme` props. Asciidoctor is not mocked. The test loads the real library with `document.currentScript` and `process.argv` patched only while it loads, so the assertions check real AsciiDoc output.

What I'm deliberately not changing:

- `page.jsx`, `Editor.jsx`, and `navbar.jsx`. This PR adds tests only.
- `jest.config.js`, `jest.setup.js`, and `package.json`. No new dependencies.
- Docs. The issue asks for instructions on running the tests, but contributing.md ("Run the Tests") and the README ("Running the Tests", from #696) already have them, so I won't add a second copy.

**Implementation Plan**

1. Add `__tests__/asciiDoc/page.test.jsx` with the Monaco mock and the jsdom patch for Asciidoctor, plus small helpers to find the editor and the preview. The preview has no role or label, so the tests find it as the editor's next sibling.
2. Write the rendering, interaction, theme, and workflow tests described above.
3. Run the new suite, then the whole suite with coverage, and confirm `src/app/asciiDoc/` goes from 0% to full coverage with every existing suite still passing.
4. Break `page.jsx` on purpose (skip the conversion, and lock the editor theme) to confirm the new tests fail. Then restore it, so none of those edits are in the PR.
5. Run Prettier on the new file, which is what the repo's `format.yml` check and pre-commit hook run.
